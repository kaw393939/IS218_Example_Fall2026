# Submission and repository access

[Course index](../README.md)

## Before submitting

Use your personal assignment repository, not the instructor example or a local
practice lab. Submit its GitHub page URL through the course submission location.
For each assignment, keep the requested issues, commit links, test results, and
verification comments in GitHub. A screenshot alone does not replace that history.

## Public repositories

Open the repository URL in a signed-out/private browser window. Confirm that the
files and required issues or pull requests are visible. Check that the URL points
to your repository, rather than a local folder or the instructor's example.

## Private repositories

1. Get the instructor's exact GitHub username through the course channel. Do not
   infer it from an example URL; teaching assistants may need separate access.
2. In the repository's **Settings**, find **Collaborators** under access management.
   Select **Add people** and invite the required reviewer account.
3. Ask the reviewer to accept. A pending invitation is not verified access.
4. Confirm the reviewer can open the repository and an issue or pull request link.
   Record that confirmation with your submission if requested.

Private repositories need not be made public. If a deadline arrives while access
is pending, submit the URL on time and explain the pending invitation through the
course channel. Never submit passwords, access tokens, or private SSH keys.

## Evidence checklist

- Assignment 0: repository URL and the requested VS Code terminal screenshot.
- Assignment 1: four closed issues, linked commits, verification comments, and a
  fresh-clone check with at least two passing tests.
- Assignment 2: issue and merged pull request links, review evidence, and final tests.
- Assignment 3: pull request and workflow-run links showing failure and recovery.
- Practice labs: provide the specific checkpoint evidence only if assigned.

Submission receives credit under the instructor's course policy. These checklists
make completion reviewable; they do not introduce a separate grading scheme.

See [GitHub's collaborator instructions](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/inviting-collaborators-to-a-personal-repository).
